# 一觉起来发生了啥？

个人用 ACG 早报：每天早上自动抓取游戏 / 动画 / 漫画 / 电影 / 音乐五个板块的新闻，
按"事情大小"排序，每个板块展示 5 条。某板块当天真的没内容时，就送一句名台词。
如果当天有高人气角色过生日，页面顶部还会出现一条生日彩蛋。
页面底部另外附「每日一句」（每天固定一句，且不会和占位名句撞车），
以及「历史上的今天」——只挑 ACG 圈里当天最大件的几件事（游戏发售 / 动画开播 /
剧场版上映 / 漫画开始连载）。

## 日常使用

| 想做的事 | 怎么做 |
| --- | --- |
| 看今天的早报 | 打开云端网址（见下方「云端部署」），或双击 `index.html` |
| 手动更新 | 双击 `更新早报.cmd` |
| 本机每天自动更新 | 双击 `安装定时任务.cmd`（默认早上 07:00，需开机） |
| 取消自动更新 | 双击 `卸载定时任务.cmd` |

页面可以离线打开，历史数据存在 `data/` 里，最多保留 7 天，可用顶部日期条回看。

## 云端部署（推荐）

已经接好 GitHub Actions + GitHub Pages，电脑关机也会照常更新。

**首次配置（只做一次）：**

1. 在 GitHub 上新建一个 **Public** 空仓库（不要勾选 README / .gitignore）。
2. 把本仓库推上去（第一次 push 会弹出浏览器登录 GitHub）。
3. 仓库 **Settings → Pages → Source** 选 `Deploy from a branch`，
   Branch 选 `main`，目录选 `/ (root)`，保存。
4. 等 1～2 分钟，访问 `https://<你的用户名>.github.io/<仓库名>/`。
5. 到 **Actions** 标签页点一次 `Run workflow` 验证流水线能跑通。

**之后就是全自动的：**

- 每天北京时间 **07:00**（`cron: 0 23 * * *`）自动抓取并提交数据，Pages 随后自动重新发布。
- GitHub 的定时任务在高峰期可能延迟几分钟到半小时，不影响使用。
- 想立刻更新：仓库 **Actions → 每日早报更新 → Run workflow**。

如果双击 `index.html` 后显示「还没有早报数据」，说明 `data/brief.js` 还没生成，
先双击 `更新早报.cmd` 跑一次即可。

想在浏览器里预览（比如换设备看），可以运行 `node scripts/serve.mjs`，
然后访问 http://localhost:8123 。

## 目录结构

```
index.html            页面本体
assets/style.css      样式（深色现代简约）
assets/app.js         渲染逻辑
data/brief.js         前端读取的数据（脚本自动生成）
data/quotes.json      名句库（可自由增删）
data/onthisday.json   ACG「历史上的今天」缓存（全年 366 天，脚本生成）
data/birthdays.json   角色生日表（2811 个高人气角色）
data/YYYY-MM-DD.json  每日存档
scripts/build.mjs     早报生成主脚本
scripts/build-birthdays.mjs  角色生日表生成脚本
scripts/build-onthisday.mjs  ACG「历史上的今天」抓取脚本
scripts/sources.mjs   数据源配置
scripts/lib/          抓取、解析、分流、打分
scripts/probe*.mjs    数据源可用性探测（排查问题用）
```

## 生成流程

```
抓取 RSS  →  过滤（氪金手游/广告/旧闻）  →  按板块分流  →  去重  →  重要性打分  →  每板块取前 5
                     ↓                                                        ↓
          头条配图（og:image）                                    无内容的板块 → 名句
                     ↓
             每日一句 + ACG「历史上的今天」（按日期从缓存里取）
```

全程由 Node 脚本完成，**不调用 AI，不消耗 token**。

## 打分规则（决定"事情大小"）

加分：讣告、动画化/实写化/续篇、发售日决定、受赏、记录突破、延期/中止、独占速报、
主机与单机向关键词、日系内容、站点权重、时效性。

减分：采访/专栏/考察/排行榜、打折促销、周边与抽选、口碑反应类、未确认传闻、
欧美站的 review/guide/deals。

直接排除：氪金手游与抽卡相关内容（ガチャ / ソシャゲ / 事前登録 / 卡池 / 抽卡等）。

## 数据源

本机可用 28 个源，全部经过实测。另外还有 7 个「仅云端」源（コミックナタリー、
映画ナタリー、音楽ナタリー、ANN、ORICON、映画.com），它们在国内网络下被墙或被反爬拦截，
跑在 GitHub Actions 上时才会启用——云端版的漫画板块会比本地版厚很多。

游戏板块最厚（9 源），漫画硬新闻最少，因此漫画板块在新闻不足时会用
「更新」条目（各漫画站当日更新的章节）补齐。

想加源或删源：编辑 `scripts/sources.mjs` 即可；
不确定某个源能不能用，先跑 `node scripts/probe.mjs` 探测。

## 名句库

`data/quotes.json`，按板块分类，格式为 `{ text, author, work }`。
每天的句子由日期决定，同一天刷新不会变。想换就直接改这个文件。

## 每日一句

页面最底部那条「每日一句」，句子就来自上面那个名句库 `data/quotes.json`
（各板块摊平后一起抽，同一个人的同一句话不会重复出现）。规则：

- 由日期决定，同一天怎么刷新都是同一句；
- 自动避开最近 7 天已经出现过的句子；
- **不会和当天某板块"无新闻时的占位名句"重复**（就算占位名句刚好被抽中，也会顺延到下一句）。

想换句子直接改 `data/quotes.json` 就行，占位名句和每日一句会一起生效。

## ACG「历史上的今天」

页面最底部的板块，只放 ACG 领域的大事，每天最多 4 件：

- 游戏发售、动画开播、剧场版上映、漫画开始连载，四类各最多占 2 条；
- 一个作品有多条发售日（移植 / 各区发售）时只认**最早**那条；
- 用 Wikidata 的 sitelinks（条目被多少个语言版本收录）当作"够不够大"的尺子，取最大的几件。

数据缓存在 `data/onthisday.json`，**全年 366 天都在仓库里**，所以页面离线也能看。
想更新（比如想收录更多冷门作品）执行：

```
node scripts/build-onthisday.mjs --all
```

只补未来 60 天缺的日子用默认命令即可（`node scripts/build-onthisday.mjs`）。
注意：Wikidata 在国内网络下直连不通，本机跑这个脚本需要先设置代理，例如
`$env:HTTPS_PROXY="http://127.0.0.1:7897"` 和 `$env:NODE_USE_ENV_PROXY="1"`（Node 24+）。
GitHub Actions 上直连即可，工作流每天会自动补齐缺的日子，失败也不影响早报。

## 角色生日彩蛋

当天若有角色过生日，页面顶部会显示「今天是 XXX（作品）的生日 · 生日快乐！」，
最多同时报 3 位（按人气排序），没有生日就完全不显示。

数据来自 [AniList](https://anilist.co) 的公开 GraphQL API：取收藏数最高的 5000 个角色，
过滤掉人气值低于 40 的冷门角色，最终收录 2811 个、覆盖 364 天，存在 `data/birthdays.json`。

想更新或扩充这份生日表（比如以后想收录更多角色），运行：

```
node scripts/build-birthdays.mjs --pages=100
```

想只看数据结构不对文件写入：`node scripts/build-birthdays.mjs --probe`。
收录门槛在脚本顶部的 `MIN_FAVOURITES`，想更"大众向"就把它调高。

## 已知限制

- 需要联网才能更新；断网时页面显示的是上一次的数据。
- 「历史上的今天」的数据取自 Wikidata，国内直连不通；缓存已经随仓库提交，
  所以页面照常显示，但想在本机刷新需要挂代理（见上方「ACG 历史上的今天」）。
- 以下站点在国内网络下不可达或做了反爬，已从源列表剔除：
  natalie.mu（コミック/映画/音楽ナタリー）、Anime News Network、ORICON、
  映画.com、Google News、Hatena 书签、Crunchyroll。
- 日文标题保持原文（按需求暂不翻译）。
